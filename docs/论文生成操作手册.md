# BDCI AI 论文生成操作手册

本文档针对 `D:\\File\\BDCI\\bdci` 项目，说明如何从环境检查、研究运行到论文编译和提交前核验。项目是**受监督的证据驱动研究流水线**：模型只负责受限任务，研究问题、实验协议、证据绑定和最终接受由人工确认。它不会自动向比赛网站提交论文。

## 一、先判断要走哪条路径

| 目标 | 推荐入口 | 是否需要 API Key | 结果 |
|---|---|---:|---|
| 验证环境、复现仓库已有结果 | `scripts/audit_v4.py`、`paper/v4/paper.pdf` | 否 | 离线审计和已有 PDF |
| 用已有 V4 证据重新编译 PDF | `scripts/build_paper_v4.py` | 否（脚本本身不调用模型） | `paper/v4/paper.pdf` |
| 从零开展一个新课题并生成论文 | `research_lab project ...` | 研究阶段通常需要 | 新项目目录中的证据、草稿和人工审阅后的论文 |
| 运行旧的 STALE 复现入口 | `research_lab.study` | 视读者阶段而定 | 仅作复现起点，不能直接宣称新发现 |

第一次使用建议先完成“离线最小验证”，确认 Python、依赖、上游源码和测试均正常，再决定是否消耗模型额度。

## 二、环境准备（Windows PowerShell）

在 PowerShell 中执行：

```powershell
cd D:\\File\\BDCI\\bdci
py -3.12 -m venv .venv
.\\.venv\\Scripts\\python.exe -m pip install -r requirements.lock
.\\.venv\\Scripts\\python.exe -m pip install --no-deps -e .
$env:PYTHONUTF8 = "1"
```

项目已带 `.venv` 时可跳过创建虚拟环境，但仍应使用 `.venv\\Scripts\\python.exe`，不要混用系统 Python。需要联网下载固定的上游源码时执行：

```powershell
.\\.venv\\Scripts\\python.exe scripts/bootstrap_v4.py
```

如果仓库中只有 `scripts/bootstrap_v4.py`，它是 V4 研究资产下载器，会访问 Hugging Face 并下载 STALE 数据；不要在没有确认磁盘空间和网络权限时运行。

先运行单元测试和项目验证：

```powershell
.\\.venv\\Scripts\\python.exe -m pytest -q
.\\.venv\\Scripts\\python.exe -m research_lab project doctor
.\\.venv\\Scripts\\python.exe scripts/verify_projects_v5.py --output projects/local-check-01
```

## 四、复现已有 V4 论文

### 4.1 运行离线科学审计

```powershell
.\\.venv\\Scripts\\python.exe scripts/audit_v4.py
```

该脚本检查冻结协议的 SHA-256、development/heldout 划分、320 个 held-out 场景的确定性检索结果以及读者上下文哈希。它不联网、不调用模型、不改变论文结论。失败时先检查 `research/v4/frozen.json` 中的源文件哈希和 `research/v4/assets/stale/T1_T2_400_FULL.json` 是否完整。

### 4.2 编译已有论文

```powershell
.\\.venv\\Scripts\\python.exe scripts/build_paper_v4.py
```

脚本读取 `research/v4/model-sections-core.json`、`heldout-rows.json`、`paired.json` 和文献注册表，把经过监督者修改的段落与真实证据绑定，生成 `paper/v4/paper.tex`、`paper/v4/document.json` 和 PDF。需要本机安装 `pdflatex`；若不编译，仓库已有 `paper/v4/paper.pdf` 可供查看。

可用环境变量指定 TeX 程序：

```powershell
$env:RESEARCH_LAB_TEX_BINARY = "pdflatex"
```

### 4.3 生成发布前元数据（不代表正式提交）

```powershell
.\\.venv\\Scripts\\python.exe scripts/finalize_v4.py
```

此步骤校验论文 claims/evidence 绑定并写入 `research/v4/release-checks.json`。其中 `official_submission` 必须仍为 `False`，因为项目不会替用户向比赛或评审系统提交。

## 五、新建课题并生成论文

### 5.1 准备模型配置

先取得预算和模型授权，再配置本地文件。不要把 Key 写入 Git 跟踪文件：

```powershell
Copy-Item .env.example .env
```

编辑 `.env`，填入 `DEEPSEEK_API_KEY` 和 `RESEARCH_KIMI_API_KEY`。编辑 `.local/models.json`（若不存在，按 README 中的配置模板创建），为 `deepseek`、`kimi` 设置真实 `base_url`、模型名、API 格式和个人预算。检查连通性会产生少量调用：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab model-check --model deepseek
.\\.venv\\Scripts\\python.exe -m research_lab model-check --model kimi
.\\.venv\\Scripts\\python.exe -m research_lab usage
```

### 5.2 创建项目协议

公开配置放在 `config/projects/`，例如复制 `config/projects/linear.json` 后修改研究问题、候选方法、预算和数据路径。先验证，再初始化唯一项目 ID：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project validate config/projects/my-study.json
.\\.venv\\Scripts\\python.exe -m research_lab project init projects/alice-my-study-01 --config config/projects/my-study.json
```

项目 ID 不要复用；改研究方案应新建项目，保留旧项目的失败记录和证据。

### 5.3 按阶段推进，每阶段先审阅再决定

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project status projects/alice-my-study-01
.\\.venv\\Scripts\\python.exe -m research_lab project advance projects/alice-my-study-01
.\\.venv\\Scripts\\python.exe -m research_lab project review projects/alice-my-study-01 brief
```

当状态为 `awaiting_review` 时，人工阅读 review、产物和 evidence，使用真实 binding 和理由作决定：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project decide projects/alice-my-study-01 brief `
  --action accept --actor alice `
  --reason "已核对研究问题、数据范围和候选方法" `
  --binding "<review 输出中的 binding>"
```

获得授权后才执行真实模型阶段：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project advance projects/alice-my-study-01 --allow-models
```

依次处理 `brief`、`design`、`freeze`、`retrieval`、`readers`、`judges`、`analysis`、`interpretation`、`draft`、`manuscript`。每次 `advance` 后都检查 `status`；不要把后台运行或历史目录当作人工验收。

### 5.4 从证据草稿到论文

最终草稿通常位于：

```text
projects/<id>/evidence/<run-id>/paper_draft.md
```

它不是可直接投稿的论文。必须补齐已核实的相关工作、方法、表格、统计不确定性、失败调用和限制，并将每条结论绑定到证据文件。使用项目的 manuscript 编译器生成结构化文档，再用目标会议模板编译 PDF。若使用 ICLR 模板，确认 `references/templates/iclr2026/` 中的 `.sty`、`.bst` 和 `.tex` 齐全，并安装 `pdflatex`。

## 七、结果位置和质量检查

- 项目状态：`projects/<id>/project-state.json`
- 阶段产物：`projects/<id>/artifacts/<stage>/<attempt>/result.json`
- 证据包：`projects/<id>/evidence/<run-id>/`
- 模型请求与结果：`outputs/<run-id>/`（含失败记录，不要删除）
- V4 研究数据和统计：`research/v4/`
- 已编译论文：`paper/v4/paper.pdf` 或新项目指定输出目录

提交前至少执行：

```powershell
.\\.venv\\Scripts\\python.exe scripts/audit_v4.py
.\\.venv\\Scripts\\python.exe -m pytest -q
```

人工逐页检查 PDF 的字体、图表、公式、引用、页数和是否存在未替换占位符；核对论文数字与 JSON 结果一致；运行 `scripts/check_share.py`（若仓库提供）扫描待分享文件，不得包含 `.env`、API Key、原始模型响应或私有数据。

## 八、常见问题

**找不到模块 `research_lab`**：确认当前目录是 `bdci`，并重新执行 `pip install --no-deps -e .`。

**PowerShell 中文乱码**：设置 `$env:PYTHONUTF8 = "1"`，并使用 UTF-8 编辑器。

**模型调用失败**：先运行 `model-check`；检查 Key、`base_url`、API 格式、网络和个人预算。未知用量要保留为未结算，不要把失败请求当作零成本。

**PDF 编译失败**：确认 `pdflatex` 在 PATH 中，或设置 `RESEARCH_LAB_TEX_BINARY`；先打开 `.tex` 定位缺失宏包或引用。

**项目卡在 `awaiting_review`**：这是设计行为。先 `review`，再用真实 `decide` 绑定；不要直接重复 `advance`。

**想修改已经开始的正式实验**：不要覆盖原项目；创建新项目 ID，保留原始协议、结果和失败记录。

## 九、边界与提交说明

当前仓库已有 V4 PDF 和大量历史运行目录，但这不表示当前用户已经完成新的官方提交。新的 PDF 需要匹配的评审 Access Token，比赛包还需要按官方目录补齐 `paper/paper.pdf`、`AgenticReviewer/PaperReview-AccessToken.txt`、`code/`、文档、资源报告和提交说明。Token 不应复用历史凭证；最终上传、公开 PR 和比赛提交必须由项目负责人按官方要求人工完成。

## 十、基于已有题目重写论文（STALE 实际流程）

本节记录已经实际跑通的流程：使用仓库已有的 STALE 题目和公开数据，创建一个新的、独立的监督式复现项目，重新生成分析、读者评审和论文草稿。该流程不会覆盖历史 `research/v4` 结果，也不会把已有论文直接当作新项目结果。

### 10.1 确认 STALE 数据

仓库已有完整数据时，先检查文件：

```powershell
Test-Path research/v4/assets/stale/T1_T2_400_FULL.json
Get-Item research/v4/assets/stale/T1_T2_400_FULL.json | Select-Object Length
```

数据文件约 306 MB，包含 400 个场景。若文件不存在，可按项目说明使用 `scripts/bootstrap_v4.py` 下载并保存数据许可证。不要把同一数据集误称为全新盲测数据。

### 10.2 创建新的唯一项目

基于已有 STALE 题目运行 `research_lab.study`。项目 ID 必须唯一；下面的 ID 仅作为示例，已经使用过的 ID 不能再次执行：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab.study `
  --id alice-stale-replication-01 `
  --dataset research/v4/assets/stale/T1_T2_400_FULL.json `
  --readers-per-type 2 `
  --seed alice-stale-20261003
```

初始化会创建：

```text
projects/alice-stale-replication-01/
.local/study-configs/alice-stale-replication-01/
```

项目协议会固定研究问题、数据哈希、读者 UID、随机种子、源代码哈希、限制条件和“复现而非新发现”的边界。

### 10.3 首次推进与 brief 验收

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project status `
  projects/alice-stale-replication-01

.\\.venv\\Scripts\\python.exe -m research_lab project advance `
  projects/alice-stale-replication-01

.\\.venv\\Scripts\\python.exe -m research_lab project review `
  projects/alice-stale-replication-01 brief
```

`review` 输出包含 `binding`。确认研究问题、数据范围和限制后，使用真实 binding 验收：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project decide `
  projects/alice-stale-replication-01 brief `
  --action accept `
  --actor user-supervisor `
  --reason "确认使用公开 STALE 数据进行受限复现，不宣称新发现" `
  --binding "<brief review 输出中的 binding>"
```

### 10.4 设计审查和协议冻结

授权模型调用后推进设计阶段：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project advance `
  projects/alice-stale-replication-01 --allow-models
```

查看设计审查：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project review `
  projects/alice-stale-replication-01 design
```

STALE 复现中应特别核对：

- 句子级和 turn 级切分导致的长度混淆；
- 4096 字节截断和打包顺序；
- BM25 参数、分词和 tie-break 规则；
- 词法包含指标不能等同于回答正确率；
- 模型读者和模型评审的偏差；
- 已使用数据不能产生新颖性声明；
- `oracle` 边界和金标准来源必须如实记录。

接受设计后冻结协议：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project decide `
  projects/alice-stale-replication-01 design `
  --action accept --actor user-supervisor `
  --reason "接受为受限 STALE 复现，保留设计审查列出的全部限制" `
  --binding "<design review 输出中的 binding>"

.\\.venv\\Scripts\\python.exe -m research_lab project advance `
  projects/alice-stale-replication-01

.\\.venv\\Scripts\\python.exe -m research_lab project review `
  projects/alice-stale-replication-01 freeze
```

冻结阶段接受后，不再修改研究问题、数据、读者样本、指标或源代码哈希。若必须修改，应创建新的项目 ID。

### 10.5 执行检索、读者和评审阶段

接受 `freeze` 后执行：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project decide `
  projects/alice-stale-replication-01 freeze `
  --action accept --actor user-supervisor `
  --reason "冻结公开数据复现协议，不调参、不宣称新颖性" `
  --binding "<freeze review 输出中的 binding>"

.\\.venv\\Scripts\\python.exe -m research_lab project advance `
  projects/alice-stale-replication-01 --allow-models
```

检索阶段是确定性计算，可能显示类似 `Retrieval 20/400` 的进度；读者阶段会调用配置好的 DeepSeek 和 Kimi。每个阶段完成后都要：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project status `
  projects/alice-stale-replication-01

.\\.venv\\Scripts\\python.exe -m research_lab project review `
  projects/alice-stale-replication-01 retrieval

.\\.venv\\Scripts\\python.exe -m research_lab project review `
  projects/alice-stale-replication-01 readers
```

确认产物、失败记录、模型用量和限制后，分别用 `decide --action accept` 验收 `retrieval` 和 `readers`。随后再次执行 `advance --allow-models` 运行 `judges`。评审结果只能称为模型评审结果，不得写成人工准确率。

### 10.6 分析、解释和论文草稿

验收 `judges` 后继续推进：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project advance `
  projects/alice-stale-replication-01 --allow-models
```

依次验收：

```text
analysis → interpretation → draft → manuscript
```

每个阶段均使用同一模式：

```powershell
.\\.venv\\Scripts\\python.exe -m research_lab project review <项目目录> <阶段>
.\\.venv\\Scripts\\python.exe -m research_lab project decide <项目目录> <阶段> --action accept --actor user-supervisor --reason "实际核对产物和证据" --binding "<review binding>"
.\\.venv\\Scripts\\python.exe -m research_lab project advance <项目目录> --allow-models
```

完成 `manuscript` 后，论文草稿通常位于：

```text
projects/<项目ID>/evidence/<run-id>/paper_draft.md
```

同时保留：

```text
projects/<项目ID>/evidence/<run-id>/evidence.json
projects/<项目ID>/project-state.json
projects/<项目ID>/artifacts/<stage>/<attempt>/result.json
```

### 10.7 从 STALE 草稿编译正式 PDF

`paper_draft.md` 是已绑定证据的待编辑草稿，不是最终投稿文件。编译前人工补齐引用、方法、表格、图、统计说明和限制，然后使用会议模板生成 LaTeX。已有 V4 论文的编译入口是：

```powershell
.\\.venv\\Scripts\\python.exe scripts/build_paper_v4.py
```

它生成的是 `paper/v4/paper.pdf`，绑定的是既有 V4 证据。新 STALE 项目应先把草稿和项目证据整理为新的结构化 `document.json`，再调用 `research_lab.manuscript.compile_document`，不要直接覆盖或冒充 V4 结果。

### 10.8 完成判定

只有同时满足以下条件，才可以称为“项目流程完成”：

- `project status` 显示 `completed`；
- 所有阶段都有人工验收 decision 和 binding；
- 论文草稿中的数字与 `evidence.json` 一致；
- 模型失败、未知用量和未评分样本没有被删除；
- 草稿明确标注 STALE 复现、已使用数据和研究限制；
- PDF 经过人工逐页检查；
- 新 PDF 的评审凭证、资源报告和提交说明已单独准备。

流程完成不等于比赛提交完成。正式投稿、上传评审系统和公开 PR 仍需项目负责人依据官方要求人工执行。

### 10.9 实例：把本次 STALE 草稿转换为独立 `document.json`

本次实际运行生成的输入文件是：

```text
projects/alice-stale-replication-01/evidence/31e24438f798-manuscript-1/paper_draft.md
projects/alice-stale-replication-01/evidence/31e24438f798-manuscript-1/evidence.json
projects/alice-stale-replication-01/evidence/31e24438f798-analysis-1/reader-analysis.json
projects/alice-stale-replication-01/evidence/31e24438f798-retrieval-1/retrieval-summary.json
```

不要把 `paper_draft.md` 直接复制到 `paper/v4/`，也不要直接修改 `research/v4/document.json`。先创建本项目专属输出目录：

```powershell
New-Item -ItemType Directory -Force paper/stale-replication-01 | Out-Null
```

然后建立一个新的结构化文档。下面是针对本次实际结果的最小示例，保存为临时文件 `paper/stale-replication-01/build_document.py`：

```python
import json
from pathlib import Path
import sys

ROOT = Path(r"D:/File/BDCI/bdci")
sys.path.insert(0, str(ROOT / "src"))
from research_lab.manuscript import compile_document
from research_lab.storage import digest, read_json, write_json

PROJECT = ROOT / "projects/alice-stale-replication-01"
OUTPUT = ROOT / "paper/stale-replication-01"
analysis = read_json(PROJECT / "evidence/31e24438f798-analysis-1/reader-analysis.json")
retrieval = read_json(PROJECT / "evidence/31e24438f798-retrieval-1/retrieval-summary.json")

retrieval_path = PROJECT / "evidence/31e24438f798-retrieval-1/retrieval-summary.json"
analysis_path = PROJECT / "evidence/31e24438f798-analysis-1/reader-analysis.json"

primary = retrieval["retrieval_primary"]
primary_text = (
    f"The pre-registered sentence_bm25 minus turn_bm25 contrast was "
    f"{primary['mean']:.3f} (95% interval "
    f"{primary['ci95'][0]:.3f} to {primary['ci95'][1]:.3f}) "
    f"over {primary['n']} scenarios."
)
reader_text = (
    f"The reader pilot attempted {analysis['reader_attempted']} responses and "
    f"graded {analysis['reader_graded']}; it is a small model-judged pilot, "
    "not human validation."
)

document = {
    "title": "Sentence- versus Turn-Level Retrieval: A STALE Replication",
    "author": "Team Neng Gong Zhi Ren",
    "abstract": "{{C_primary}} {{C_reader}} This is a replication on previously exposed data; it makes no novelty or deployment claim.",
    "sections": [
        {
            "heading": "Introduction",
            "paragraphs": [
                "This paper revisits the existing STALE question under a fixed 4096-byte evidence budget. It compares sentence-level and turn-level retrieval on the pre-registered public dataset.",
                "{{C_primary}} The lexical inclusion outcome measures evidence availability, not semantic answer correctness."
            ]
        },
        {
            "heading": "Results and limitations",
            "paragraphs": [
                "{{C_reader}} The study uses previously exposed data, a single dataset, lexical metrics, opposite-model grading and no human validation.",
                "The empty oracle comparison and the absence of responses with new evidence present prevent causal claims about evidence causing reader success."
            ]
        }
    ],
    "references": [],
    "claims": [
        {
            "id": "C_primary",
            "text": primary_text,
            "evidence_ids": ["retrieval"]
        },
        {
            "id": "C_reader",
            "text": reader_text,
            "evidence_ids": ["analysis"]
        }
    ],
    "evidence": {
        "retrieval": {"path": str(retrieval_path), "sha256": digest(retrieval_path)},
        "analysis": {"path": str(analysis_path), "sha256": digest(analysis_path)}
    }
}

OUTPUT.mkdir(parents=True, exist_ok=True)
write_json(OUTPUT / "document.json", document)
pdf = compile_document(document, OUTPUT)
print(f"Compiled {pdf}")
```
